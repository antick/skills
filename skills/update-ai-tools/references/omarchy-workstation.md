# Owner's Omarchy workstation profile

This preserves the installation routes and exceptions from the original local
skill. Paths, package versions, channels, and package availability describe that
workstation, not every installation. Before applying a route, verify it against
the current machine and official upstream metadata. Treat example versions as
historical observations, never as the latest release.

On explicit invocation, inspect and update the listed tools; do not ask the user to repeat the list. Work from a temporary directory, never create build artifacts in the current repository. Do not upgrade the entire OS or unrelated mise tools. Preserve user data, settings, running sessions and current terminal. Never print credentials or private app window titles. Verify versions after each action and distinguish **installed**, **already current**, **staged**, and **blocked**. Do not claim an update happened when only downloaded. **AppImage rule:** install and run AppImages as the actual `.AppImage` file so the AppImage runtime exports `$APPIMAGE`; never extract one and run `AppRun` for the GUI, because `electron-updater` refuses to update without `$APPIMAGE`. Keep `fuse2` installed, and if libfuse2 is ever missing set `APPIMAGE_EXTRACT_AND_RUN=1` (which still exports `$APPIMAGE`). This applies to T3 Code Nightly, OpenCode desktop, and Orca's GUI.

## Inventory and update routes

This task explicitly overrides the machine's 24-hour release-age hold: use `mise upgrade --dry-run --minimum-release-age 0 <only those tool names>` then `mise upgrade --minimum-release-age 0 <those tool names>`. Codex is pinned in global mise config: inspect the pin and newest release (`mise upgrade --dry-run --bump --minimum-release-age 0 codex`), and when newer, run `mise upgrade --bump --minimum-release-age 0 codex` to move the pin. Herdr's Omarchy repo may lag official GitHub releases; when so, build a pacman package from the official x86_64 release binary and LICENSE, retaining the installed package's name and dependencies. T3 Code Nightly is a user-local, **self-updating AppImage**: the file is `~/.local/opt/t3code-nightly/t3code-nightly.AppImage` (keep this stable filename), launched by the FUSE-aware wrapper `~/.local/bin/t3code-nightly-appimage`, and registered by `~/.local/share/applications/t3code-nightly.desktop` (the old pacman launcher is hidden by a `Hidden=true` user override). It self-updates in-app through `electron-updater`, which requires `process.env.APPIMAGE`; any pacman/AUR package that extracts the AppImage and runs `AppRun` directly leaves `$APPIMAGE` unset and permanently breaks auto-update — so do **not** install `t3code-nightly-bin`. To update manually, download the newest nightly release asset `T3-Code-<version>-x86_64.AppImage` to that same stable path (replacing the file) and relaunch; verify `$APPIMAGE` via a targeted check of `/proc/<pid>/environ` that prints only the `APPIMAGE` entry (never the full process environment) and that the logs show a successful `desktop.updates.checkForUpdates` with no "is not an AppImage" warning. Cursor desktop is installed as the Omarchy repo package `omarchy/cursor-bin` (3.21.9 as of 2026-10), which supersedes the same-named AUR package; the AUR build is newer (3.24.12). If the owner wants the newest AUR version, in which case force the AUR build with `yay -S aur/cursor-bin`, report that you overrode the Omarchy package, and restart the app. Antigravity packages are AUR-only: compare `pacman -Q <pkg>` with the AUR RPC/PKGBUILD and `yay -Si`, then `yay -S <pkg>`; `antigravity-ide` conflicts only with `antigravity<2.0`, so it coexists with the 2.x desktop, and `antigravity-appimage` is not used (it `provides=antigravity`). ## Checks and reporting

- Discover executable paths with `type -a`, installed package ownership and version before choosing an update command. Recheck remote releases; don't pin a version from an earlier run.
- Override the 24-hour age hold with `--minimum-release-age 0`; the user's intent is newest, not newest aged release.
- **Mise wrapper guard:** `~/.local/bin` contains hand-written wrappers (`codex`, `claude`, `grok`, `gh`, `muse`, `cursor-agent`, `hermes`, `pi`, `opencode`, …) of the form `mise use -g …; exec mise x …`. Each must strip `$HOME/.local/bin` from `PATH` immediately before `exec mise x` (guard: `export PATH="$(printf '%s' "$PATH" | tr ':' '\n' | grep -vxF "$HOME/.local/bin" | paste -sd: -)"`). If any launcher puts `~/.local/bin` first on `PATH` (the T3 Code AppImage does), `mise x tool -- tool` otherwise re-execs the same wrapper and deadlocks — making every T3 provider (codex/claude/grok) and `gh` hang until they time out. Re-apply the guard if a wrapper is ever regenerated; backups live in `~/.local/state/mise-wrapper-backups/`.
- Preserve running agent sessions during install, but don't leave obsolete mise versions or versioned app duplicates after their processes exit. Never remove an executable or runtime backing the current agent session while it is running.
- Never write into this project's tracked tree; use a temporary work directory. Do not add arbitrary system packages or change the owner's pinning policy without reporting what changes.
- End every run with a Markdown **report table** covering every listed product (separate desktop and CLI rows when independently installed), with columns `Tool`, `Before`, `After / latest`, `Status` (`updated`, `already current`, `staged`, or `blocked`), and `Notes / next step` (including required restarts, privilege, or reasons for failure). Always show separate rows for Cursor CLI, Cursor desktop, Grok CLI, OpenCode CLI, OpenCode desktop, Antigravity desktop, Antigravity IDE, and Antigravity CLI (`agy`) when those tools are in scope; for Orca Desktop and Orca CLI, show both rows even though they share one install; include Herdr explicitly. Never label a download or staged package as installed.
